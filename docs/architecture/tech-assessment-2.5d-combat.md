# 2.5D 战斗技术可行性评估

> 项目：单机修仙 RPG（即时战斗 + 互锁箱庭地图）· PC 买断 · 中等体量（小团队）
> 美术路线：3D 低模底 + 手绘国风贴图 + 墨韵后处理（Unity URP）
> 文档状态：Phase 2 工程落盘 · 已批准

---

## 1. 技术可行性结论

**结论：可行，Unity URP 是当前路线下最合适的引擎与渲染路径。**

核心难点不在"能否实现墨韵"，而在于**如何把墨韵压进单个全屏 Pass，并与 URP Volume 体系统一雾/色调**，避免多 Pass 叠加导致中等体量 PC 帧率被后处理吃掉。固定微俯斜 45° 视角（禁自由旋转）大幅降低了深度排序与相机管理的复杂度，是 2.5D 路线能成立的前提。

---

## 2. 渲染与后处理实现

### 相机
- `Perspective` 低 FOV（25–35°），斜 45° 微俯固定机位。
- 近大远小透视契合"墨晕扩散"观感，同时规避大角度畸变导致的墨线抖动。

### 墨韵栈（Ink Stack，合并为单条自定义 Render Feature）
| 层级 | 实现要点 |
|------|----------|
| 屏幕空间墨线 | Sobel 基于 **深度缓冲**（法线缓冲暂未接入，见下方"已知偏差"）；粗细**墨渍化**（可变宽度 + 噪声扰动），非硬边描线 |
| 纸纹 | tiling 噪声纹理 **Multiply** 混合，低强度，统一"宣纸"底 |
| 渍墨 | 边缘 mask 外扩 + 噪声 alpha，模拟墨在纸上的晕开 |
| 飞白 | 程序噪声阈值打孔（threshold cutout），制造枯笔留白 |
| 法术写意 | 一笔写意笔触，非粒子光污染；当前依赖**墨线**实现（笔触法线暂未接入，见下方"已知偏差"），而非 Bloom |

> **⚠️ 已知偏差（与实装代码对齐）**：当前 `InkFullscreen.shader` 的墨线**仅采样深度缓冲（`_CameraDepthTexture`）**，**未接入法线缓冲**。因此「墨线粗细随法线变化」「笔触法线驱动的法术写意」等效果**当前不可实现**。临时替代路径：把笔触/法线感**烘焙进 albedo 贴图**（美术在贴图里画好笔触明暗）。若要真正接入法线，需在 Ink Render Feature 里额外 `ConfigureInput(Normals)` 并改造 Shader——列为后续增强项，不阻塞生产。

### 雾与色调
- **Height Fog 单 Pass**（<1ms）压远，替代真体积 raymarch。
- **Volume Color Grading**：低饱和冷调统一全场景。
- **Bloom 仅给法宝辉光**（Emissive 驱动），严禁全场景泛光。

## 3. 中等体量 PC 性能预算表（目标 1080p60）

| 维度 | 预算 |
|------|------|
| Draw Call | < 2000（SRP Batcher + 静态合批） |
| LOD | 环境 3–4 级 / 角色 2–3 级 |
| 贴图 | 主角/关键 2K，通用 1K；BC7 + Mipmap + 图集 |
| 动态光 | 1 主方向光（烘焙 GI）+ 每场景 1–3 实时点/面光（Forward+） |
| 体积雾 | Height Fog < 1ms，禁真体积 raymarch |
| 墨韵后处理 | 合并单全屏 Pass，部分半分辨率，< 2–3ms |
| CPU 主线程 | < 16ms |

## 4. 主要技术风险与缓解

| 风险 | 缓解 |
|------|------|
| 墨水 Pass 过度绘制、跨版本 API 漂移 | 全部合并单 Pass；锁 Unity LTS；抽象 `IInkPass` 接口隔离引擎 API |
| 固定相机 2.5D 深度排序错误 | Sorting Group + 自定义 Y-Z 排序轴（非纯 Z） |
| cel 描边与屏幕墨线双描边脏化 | 统一屏幕空间优先，角色描边交给 Ink Pass，关掉几何描边 |

## 5. 即时战斗原型须验证核心技术点清单

1. 角色国风着色器：Toon Ramp + Rim + 笔触法线 + 屏幕墨线。
2. Z 轴分层 / 地面空中分离（战斗可读性基础）。
3. 闪避帧 / 格挡 / 法器弹幕（对象池）。
4. 打击感：顿帧 + 墨溅 + 震屏 + DOF。
5. 动态光照：灵气/法宝辉光（Emissive + Bloom + 点光），Height Fog 响应。

## 6. 基础层 ADR 候选

- **ADR-001 引擎选型 Unity URP Forward+**
  备选：HDRP（过重，PC 买断中等体量不需要）、Built-in（已弃）、Godot（团队 Unity 熟练度更高）。决定：锁 Unity LTS。
- **ADR-002 渲染管线与后处理**
  = Volume（色调/雾）+ 单条自定义 Ink Render Feature 全屏 Pass；墨水逻辑抽象为接口。
  ⚠️ Unity 6.x RenderGraph API 已变更 → 锁版本 + 写回归测试。
- **ADR-003 资产规范命名 `CAT_SubType_Variant_LOD`**
  贴图两级（2K/1K）+ 图集 + Mipmap + 笔触法线 authoring 规范。

## 7. 风险与缓解汇总

| 类别 | 风险 | 缓解 |
|------|------|------|
| 性能 | 后处理占比过高 | 单全屏 Pass + 半分辨率 + 严格预算表 |
| 着色器跨版本 | Unity 升级 API 漂移 | 锁 LTS + 抽象接口 + 回归 |
| 小团队 VFX 蔓延 | 写意变光污染 | Bloom 仅法宝；美术规范约束 |
| 美术管线衔接 | 笔触法线/贴图标准缺失 | ADR-003 命名与 authoring 规范前置 |
