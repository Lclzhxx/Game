## 步骤 1 · 装 Unity 2022.3.62 LTS（B1）

> 为什么必须锁死这个版本：我们的「水墨画面」效果在不同 Unity 版本接口不一样。装错（尤其装成 **Unity 6**）一定会大面积报错，甚至把已验证的墨韵着色器搞崩。所以**只装 2022.3 的 LTS，且只装 2022.3.62 这个补丁**。

### 动作
1. 打开 **Unity Hub**（任务一里装的游戏引擎启动器）。左侧点「安装 / Installs」。
2. 点「安装编辑器 / Install Editor」，在列表里搜 `2022.3`，找到 **Unity 2022.3.62 LTS**（认准 **LTS** 三个字母；**不要**带 `a/b/c` 的测试版，**绝对不要**选「Unity 6」）。
   - 中国区下载到的版本号可能显示成 `2022.3.62f3c1`（多了个 `c`，是「中国特供版」），**和 `2022.3.62f1` 是同一套接口，都算对**。关键：前一段 `2022.3.62` 必须一致。
3. 右边勾选模块，至少勾上：
   - **Microsoft Visual Studio**（写代码的人用，你勾上就行）
   - **Windows Build Support (IL2CPP)**（自动打包 Windows 试玩包必须，默认常勾；**务必确认勾上**）
4. 点「安装」，等 20–40 分钟（看网速）。

### 预期结果
- Unity Hub「安装」里出现 **Unity 2022.3.62 LTS**（或 `2022.3.62f3c1`）。
- 你能确认它**不是** Unity 6、不是别的 2022.3.x 小版本（比如 2022.3.10）。

### 卡住时怎么办
| 现象 | 办法 |
|------|------|
| 列表里搜不到 2022.3.62 | 确认 Unity Hub 是最新版（任务一装的）；或用搜索框精确搜 `2022.3.62` |
| 装到一半报错 | 关掉 Hub，右键图标「以管理员身份运行」再装 |
| 不小心装成别的版本 | 「安装」里把错的卸载，重装 2022.3.62 LTS |
| 分不清是不是中国区版 | 只要版本号开头是 `2022.3.62` 就对，后面的 `f1`/`f3c1` 不影响 |

### 完成后告诉程基岩什么
> 「我装好了 **Unity 2022.3.62**（具体显示 `2022.3.62f1` 或 `2022.3.62f3c1`），并勾了 Windows Build Support (IL2CPP)。」

## 步骤 2 · 装 Git 和 Git LFS（B2 前半）

> 干什么用：Git 是「版本管理」工具（像游戏存档的时光机，能回退、能看谁改了啥）；Git LFS 专门管大文件（贴图/模型/音频），不然仓库会大到传不动。你只需装好，工程侧来用。

### 动作
1. 浏览器打开 `git-scm.com` → 下载 **Git for Windows** → 双击安装，**一路「Next / 下一步」**用默认选项即可（重点：勾选「Git from the command line」）。
2. 浏览器打开 `git-lfs.com` → 下载 **Git LFS** → 双击安装，一路下一步。
3. 验证（可选，不强制懂）：按 `Win` 键输入 `cmd` 打开黑框，分别输入 `git --version` 和 `git lfs version`，能显示版本号就装好了。

### 预期结果
- 电脑里有了 Git 和 Git LFS（看不到图标没关系，后台能用就行）。

### 卡住时怎么办
| 现象 | 办法 |
|------|------|
| 下载慢/卡 | 换网络（手机热点）重试 |
| 安装报错 | 关掉重装；或右键安装包「以管理员身份运行」 |

### 完成后告诉程基岩什么
> 你装好后不用单独汇报这步，它和「步骤 3 建仓库」一起算 B2 完成。

## 步骤 3 · 建 GitHub 私人仓库（B2 后半）

> 干什么用：这是游戏的「云端保险箱 + 协作中心」。工程侧把代码传上去，自动构建也从这里触发。选**私人（Private）**，因为项目没公开。免费额度够用（含 1GB 大文件空间）。

### 动作
1. 浏览器打开 `github.com` → 用邮箱注册/登录（免费）。
2. 右上角「+」→「New repository / 新建仓库」。
3. 填法：
   - **Repository name / 仓库名**：比如 `mijing-fanchen`（秘境·凡尘拼音，随便起，好记就行）。
   - **Private / 私人**：务必选 **Private**（别选 Public）。
   - 其余默认（**不要**勾「Add a README」也行，工程侧会建）。
4. 点「Create repository / 创建」。
5. 记下仓库网址（形如 `https://github.com/你的用户名/mijing-fanchen`），发给我。

### 预期结果
- 你有一个**私人**的空仓库，网页能打开，地址发给了我。

### 卡住时怎么办
| 现象 | 办法 |
|------|------|
| 不会用 GitHub | 不用学太多；建好私人空仓库、把网址发我就行 |
| 邮箱收不到验证信 | 看垃圾邮件；或换邮箱 |
| 1GB 大文件空间不够（以后美术资产多时） | 先不用管；真超了我会建议迁到「自托管 Gitea + 本地 LFS」，仍零费用（已在决策里拍板） |

### 完成后告诉程基岩什么
> 「GitHub 私人仓库建好了：<仓库网址>。」（这一步 + 步骤 2 = **B2 完成**）

## 步骤 4 · 配自托管构建小工人 runner（B3）

> 干什么用：这是 Sprint 1 最关键、也最像「技术活」的一步，但本质是「装一个后台小程序 + 填两个码」。它让你的电脑在每次上传代码时，**自动用你刚装的 Unity 2022.3.62 打包游戏、跑墨韵回归和帧率检查**。因为跑在你自己机器上，所以**不花云端分钟费**（决策 Q1 零收费路径）。
>
> ⚠️ 这步需要你本机 **Unity 2022.3.62 已装好（步骤 1）+ 一个有效的 Unity 许可证**。Unity 个人版（Personal，免费）就能跑 CI；若以后批量构建再考虑 Plus/Pro 的 CI 授权。

### 动作
1. 打开你刚建的 GitHub 仓库网页 → 点 `Settings`（设置）→ 左侧 `Actions` → `Runners` → 点 `New self-hosted runner`（新建自托管 runner）。
2. 选 **Windows** → 页面会给你一段「下载 + 配置」命令。照着做：
   - 下载 runner 压缩包，解压到一个文件夹（比如 `C:\actions-runner\`）。
   - 在那个文件夹里打开 `cmd`（地址栏输入 `cmd` 回车），**逐行复制页面里的命令执行**：
     - `.\config.cmd` 运行时问你：`Enter your repository` → 回车用默认的（就是当前仓库）；`runner group` → 回车；`runner name` → 回车用默认；`work folder` → 回车用 `_work`。
     - 到「用哪种方式运行」时，选 **作为服务运行（run as service）** 最省心（开机自启，后台跑）。
3. **激活 Unity 许可证（填一个「密钥」到仓库）**：
   - 你本机 Unity 已经登录过账号、有有效许可证。工程侧会给你一条命令/脚本，在你的机器上导出许可证文件，生成一串文本（叫 `UNITY_LICENSE`）。
   - 回到 GitHub 仓库 `Settings` → `Secrets and variables` → `Actions` → `New repository secret`：名字填 **`UNITY_LICENSE`**，值粘贴那串文本 → `Add secret`。
   - ⚠️ 这串文本**只存 GitHub 私密处，不进代码、不发给我明文**。
4. 回到 runner 文件夹，确认小工人已连上：GitHub 仓库 `Settings → Actions → Runners` 里能看到你的 runner 显示 **Idle（空闲，已在线）**。

### 预期结果
- GitHub 仓库的 Runners 列表里，你的机器显示 **Idle / 在线**。
- 仓库 Secrets 里多了 `UNITY_LICENSE`。

### 卡住时怎么办
| 现象 | 办法 |
|------|------|
| `config.cmd` 要填 token/URL | 那是页面上给你的「配置命令」里自带的长串，整段复制别漏；token 过期就回页面点「重新生成」 |
| runner 显示 Offline | 确认 `config.cmd` 跑完、且服务在跑（任务管理器看 `actions.runner` 进程）；或重跑一遍 |
| 没有 Unity 许可证 | 打开 Unity Hub 登录你的免费账号即自动有 Personal 许可证；导出步骤我会单独给你脚本 |
| 不知道「服务」怎么选 | 选「作为服务运行」最稳；不选也行，但每次要手动开一个小黑窗 |
| 机器配置担心不够 | 见文末「机器规格假设」，基本家用游戏本/台式都够；不够我再建议专用构建机 |

### 完成后告诉程基岩什么
> 「自托管 runner 已在线（GitHub 里显示 Idle），`UNITY_LICENSE` 已存到仓库 Secrets。」（= **B3 完成**）

## 步骤 5 · 首次 clone（下载）并打开工程

> 等工程侧把 S1 地基推上 `main` 后，你第一次把云端工程「下载」到本地、用 Unity 打开确认没报错。

### 动作
1. 工程侧会告诉你「可以 clone 了」，并给你仓库网址。
2. 在你想放工程的地方（建议 `D:\WBzone\Game\mijing-fanchen\`）打开 `cmd`，输入工程侧给你的 `git clone <仓库网址>`（会自动把大文件也拉全）。
3. 打开 **Unity Hub** → 「项目 / Projects」→「打开 / Add」→ 选中刚才 clone 下来的文件夹 → 用 **2022.3.62** 打开。
4. 等 Unity 打开 + 编译完（底部「Compiling…」消失），打开 `Console`（窗口→常规→Console）：
   - **没有红色 Error** = 成功。
   - 有红色 Error → 截图发我（你**不要**自己改）。

### 预期结果
- 工程能打开，Console **无红色错误**；能看到灰盒相关菜单（Greybox）。

### 卡住时怎么办
| 现象 | 办法 |
|------|------|
| clone 很慢 / 大文件拉不下来 | 确认步骤 2 装了 Git LFS；`git lfs pull` 手动补拉一次 |
| Unity 打开后一堆红字 | 截图发我；多半是 URP 版本被碰过，我来修 `manifest.json` |
| 打开用的是别的 Unity 版本 | 在 Hub「安装」里确认 2022.3.62 在；打开时手动选它 |
| 菜单没有 Greybox | 等编译全过；还不行就发我 Console 红字 |

## 步骤 6 · 如何「运行一次自动构建」（看 CI 是否健康）

> Sprint 1 之后，工程侧每次往 `main` 传代码，GitHub 会自动打包。你这样看它成不成功、并下载试玩包。

### 动作
1. 打开 GitHub 仓库网页 → 点顶部 `Actions`（动作）标签。
2. 看列表里叫 `Build & Smoke Test`（或 `ci`）的那条：
   - 绿色 ✓ = 成功（编译过 + 墨韵回归过 + 帧率达标）。
   - 红色 ✗ = 失败（点进去看日志，把结论告诉我，我来修）。
3. 成功的话，点进那条记录 → 右侧 `Artifacts` → 下载 `game-build`（这就是能玩的试玩包）。
4. 解压 `game-build` → 双击里面的 `.exe` 就能玩（对齐 `sprint-01-plan.md` §3 试玩窗口：灰盒 + 加固墨韵）。

### 预期结果
- 你能看懂「绿=能玩 / 红=出问题」；能下载到试玩包并双击运行。

### 卡住时怎么办
| 现象 | 办法 |
|------|------|
| Actions 里没有记录 | 工程侧还没推代码，或 runner 没在线（回步骤 4 确认 Idle） |
| 一直黄色转圈 | runner 在打包（首次慢，可能 10–30 分钟）；还卡就告诉我 |
| 红了对付不了 | 把 Actions 日志截图发我，别自己改 |
| 下载的包打不开 | 解压完整再双击；或告诉我具体报错 |

## 附 · 机器规格假设（请确认）

本清单默认你的「构建小工人」就跑在**你日常开发的这台 Windows 电脑**上，假设：

- 系统：**Windows 10 或 11（64 位）**
- 内存：**16 GB 及以上**
- 硬盘：**50 GB 及以上**空闲（Unity 本体 + 工程 Library 缓存 + 构建产物）
- 显卡：能在本机**流畅跑 1080p 游戏**的独显/核显（试玩与帧率冒烟需要）
- 已装：**Unity 2022.3.62 LTS + Windows Build Support (IL2CPP)**（步骤 1）+ **有效 Unity 许可证**（Personal 免费即可）

> 若你的机器明显低于以上（如 8GB 内存、硬盘将满），请提前告诉我——可能需要一台**专用构建机**（仍可用你另一台闲置电脑，零费用），避免打包时卡死影响进度。
